Build the vector

Base vector (CVSS-B):

CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N

Ready to score it? Paste the vector into FIRST's official CVSS v4.0 calculator, which is free and hosted by FIRST alongside the specification, user guide, and implementation guide.

Why this page does not print a score itself: the v4.0 scoring engine is a lookup over equivalence classes defined in the FIRST specification, and this site refuses to ship a second-hand reimplementation of that table that nobody here has verified line by line. A wrong severity number is worse than no number. Your vector is built locally in JavaScript and never leaves your browser, and the score comes from FIRST's own calculator one paste away.

What changed in CVSS 4.0, in plain terms

FIRST publishes CVSS v4.0 as the next generation of the Common Vulnerability Scoring System standard, and the metric set moved in ways that trip up people reusing v3.1 habits. There is a new Base metric called Attack Requirements (AT), User Interaction gained Passive and Active values, and Scope is gone, replaced by explicit impact metrics for the vulnerable system (VC/VI/VA) and for subsequent systems (SC/SI/SA). The Temporal group was renamed to Threat, and a new Supplemental Metric Group was added. All of that comes straight from the FIRST CVSS v4.0 specification.

The 4.0 standard also names four score combinations, and knowing which one you are looking at matters when a vendor publishes a number. The combinations are CVSS-B (Base), CVSS-BT (Base plus Threat), CVSS-BE (Base plus Environmental), and CVSS-BTE (Base plus Threat plus Environmental), again per the specification.

Do not score in isolation

A Base score tells you how exploitable and impactful something is in a vacuum, not whether you should drop everything. FIRST's EPSS project publishes a 0 to 1 exploitation probability plus ranking percentiles every day for every CVE, free through CSV, an API, and a GitHub repository, and FIRST's own guidance covers combining EPSS with CVSS and KEV for prioritization decisions. Both are on the FIRST EPSS page.

Where a Base score still earns its keep is deciding what to report and how to write it up. A concrete example from load-path research: PyTorch's own documentation warns that torch.load() uses an unpickler under the hood and that data must never be loaded from an untrusted source, and in the 2.14 documentation the function defaults to weights_only=True. Those two facts, from the official torch.load documentation, are exactly the kind of thing you weigh when deciding whether a deserialization finding is worth filing, and what vector its report should carry.

Severity also feeds payout expectations, soberly. HackerOne's most competitive programs, including Google, Microsoft, Apple, and Intel, have offered individual awards as high as $1,500,000 for critical issues, while its 2019 report put the average critical bounty at $3,384 across all industries. Both figures come from HackerOne's own press release. The gap between those two numbers is the entire reason this site exists, and it is why a well-built CVSS vector on your report is a triage aid, not a paycheck.

Where these numbers come from and how we know

Methodology. The vector builder above is deterministic client-side JavaScript that concatenates metric values you select into the vector string format defined by the FIRST CVSS v4.0 specification. Every factual claim on the page links to the source it came from, and the only scoring engine we point you at is FIRST's official calculator. I use CVSS scoring and EPSS data daily when deciding which of my own findings to report and in what order, which is the first-hand basis for the workflow described here. Nothing you select in the tool is transmitted anywhere; it runs entirely in your browser.

FAQ

Is this an official FIRST calculator?

No. It is an educational vector builder from Bug Bounty Reality. FIRST hosts the official free calculator at first.org/cvss/calculator/4.0, and that is where you should take the vector this page generates for the actual score.

Why no score on this page?

Because shipping an unverified reimplementation of the v4.0 scoring table would put advisory numbers in front of you with no guarantee they match the spec. The vector string is the part that is unambiguous, so this tool builds that and defers scoring to FIRST.

Do my metric selections get sent anywhere?

No. The tool runs entirely in your browser and produces simulated output, not an authoritative security assessment. No input leaves your machine.

What is the Attack Requirements metric for?

Attack Requirements (AT) is a new Base metric introduced in CVSS v4.0 that captures deployment or exploitation prerequisites beyond plain attack complexity. See the FIRST specification for its definition and scoring role.

CVSS scores are advisory inputs, not standalone measures of organizational risk. All tools run in your browser and produce estimates or simulated output, not authoritative security assessments.
