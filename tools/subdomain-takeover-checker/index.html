What is subdomain takeover?

Subdomain takeover happens when a DNS record (usually a CNAME) points to a service — S3 bucket, Heroku app, GitHub Pages site, Azure cloud app — that has been deprovisioned but not removed from DNS. Anyone can then claim that resource on the provider and serve content on your subdomain: cookie-stealing, phishing, and bypassing subdomain-based security controls all follow.

How this checker works

For each host it queries dns.google for CNAME records. If a CNAME exists, the target is matched against fingerprints of commonly-claimable services:

  • *.s3.amazonaws.com / s3-website-* — AWS S3 (bucket claim)
  • *.herokuapp.com — Heroku
  • *.github.io — GitHub Pages
  • *.azurewebsites.net / *.cloudapp.azure.com — Azure
  • *.cloudfront.net — CloudFront (distribution claim)
  • *.ghost.io, *.shopify.com, *.fastly.net, *.netlify.com, *.vercel.app and more

Risk levels

  • HIGH — dangling CNAME to a claimable service. Verify manually: visit the host and look for the provider's "NoSuchBucket"/"no app"/404 fingerprint page.
  • CHECK — CNAME to a claimable service that may or may not be registered. Manual verification required.
  • OK — resolves normally, no claimable CNAME found.

HIGH flags here are DNS-level signals only. A real takeover proof requires claiming or observing the provider error page — never test on domains without authorization, and always verify before reporting.
