Bugcrowd VRT Priority Lookup

Search the Bugcrowd Vulnerability Rating Taxonomy (VRT) and read the baseline priority of each entry. The data is VRT v1.19.1, released on 2026-07-08 and fetched from the Bugcrowd repository on 2026-10-11. The table has all 437 leaf entries with the VRT id, the priority (P1 to P5, or Varies), the mapped CWE ids and the mapped CVSS v3 vector. The priority is a baseline. A program can give your report a different rating. The lookup runs in your browser and sends no request.

The note "inherited from" shows that the mapping file has no value on the entry. The value comes from the parent entry that the note names. A value with no note is on the entry itself.

What this tool does not do

  • It does not rate your report. The VRT priority is the baseline that Bugcrowd suggests for a vulnerability class. The program decides the priority of a real report, and that priority can be different.
  • It does not calculate a CVSS score. It shows the mapped CVSS v3 vector as text. A VRT priority is not a CVSS severity.
  • It does not give a reward amount. The VRT files contain no amounts.
  • It does not update itself. It shows VRT v1.19.1 as fetched on 2026-10-11. A later VRT release can change an entry.
  • It is not a Bugcrowd product. This site is independent, and Bugcrowd does not endorse this page.

What a VRT priority means

The VRT is a public list of common vulnerability classes that Bugcrowd maintains. Each entry with no child entry has a priority value. The README of the VRT repository defines the priority in one sentence.

The priority represents Bugcrowd's suggested baseline technical severity of the vulnerability on a P1 (Critical) to P5 (Informational) scale.

VRT v1.19.1 has 581 entries in 37 top categories. 437 of them are leaf entries, which are entries with no child entry. This table shows the name of each priority and the number of leaf entries that have it.

The two Bugcrowd sources use different names for P2 and P3. The README says High and Medium. The severity overview in the customer documentation says Severe and Moderate. This page uses the README names, because the data comes from the same repository.

Varies is not P5

86 leaf entries have a null priority in the data file. The README says that a null priority "represents that the priority varies based on context information". This page shows these entries as Varies. It does not count them as P5, and it does not give them a priority from a parent entry.

The README gives Insecure Direct Object Reference as its example of a vulnerability that can vary from P4 to P1. In v1.19.1 the five IDOR entries have fixed priorities, one for each level from P1 to P5. Use the data, not the example.

A program can give a different rating

The README says that the recommended priority "might apply without context", and that "application complexity, bounty brief restrictions or unusual impact could result in a different rating". The Bugcrowd documentation for researchers has the same warning on its page about reporting a bug.

The severity rating suggested by VRT is not guaranteed to be the severity rating applied to your submission once impact is considered.

Read the program brief before you rely on a priority from this table.

How the CWE and CVSS columns are made

The taxonomy file has the id, the name and the type of each entry. It has a priority for each leaf entry and for one parent entry. The CWE ids and the CVSS v3 vectors are in two mapping files of the same repository. A mapping file does not have a value for each entry.

The inheritance rule

This page uses the rule that the README gives for mapping files. An entry with no value of its own takes the value of the nearest parent entry that has one. A value on the entry replaces the value of the parent. If no entry on the path has a value, the result is the metadata.default value of the mapping file.

value(entry) = the value on the entry, if the mapping file has one = or the value of the nearest parent that has one = or metadata.default of the mapping file

The table shows where the values of the 437 leaf entries come from. The lookup marks each inherited value with the id of the parent entry.

The default value of the CWE file is null. For that reason 138 leaf entries have no CWE id, and the lookup shows "no mapping" for them. The default value of the CVSS v3 file is AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:N. No leaf entry of v1.19.1 needs this default, because each one has a vector on itself or on a parent entry.

Points that the sources do not settle

  • CWE lists can be replaced or merged. In the README example, the value of the entry replaces the value of the parent. Bugcrowd's Ruby library, vrt-ruby, adds the CWE lists of the parents to the list of the entry. With the library rule, 154 of the 437 leaf entries get a longer CWE list. For example, SQL Injection has CWE-89 with the README rule, and CWE-89 and CWE-929 with the library rule. This page uses the README rule.
  • The CWE file has null on some entries. For 19 leaf entries the CWE file has null on the entry, and a parent entry has a list. The README does not say if a null stops the inheritance. This page shows the list of the parent for these entries and marks it as inherited.
  • The CVSS version is not given. The mapping file has the name cvss_v3. The vectors have no version prefix, and the file does not say if they are CVSS v3.0 or v3.1 vectors.
  • Bugcrowd uses two version labels. The GitHub tag of this data is v1.19.1. On 2026-10-11 the file at bugcrowd.com/vulnerability-rating-taxonomy/1.19.json was the same file, byte for byte. The labels 1.19 and v1.19.1 name the same data.

A priority is not a CVSS severity

The CVSS v3 vector is a separate mapping. It does not define the priority, and the two do not always agree. For example, 11 of the 31 leaf entries with priority P1 map to a vector that ends in C:N/I:N/A:N, which is a vector with no confidentiality, integrity or availability impact. Do not convert a VRT priority to a CVSS severity, or a CVSS score to a VRT priority.

Source, licence and changes

The data on this page is a copy of the Bugcrowd Vulnerability Rating Taxonomy, tag v1.19.1 of the repository bugcrowd/vulnerability-rating-taxonomy on GitHub. The release date in the data file is 2026-07-08. These files were fetched on 2026-10-11.

  • vulnerability-rating-taxonomy.json has the entries and the priorities.
  • mappings/cwe/cwe.json has the CWE ids.
  • mappings/cvss_v3/cvss_v3.json has the CVSS v3 vectors.
